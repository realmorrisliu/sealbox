## ADDED Requirements

### Requirement: A secret may declare when it should next be rotated

A secret MAY carry a rotation interval. The system SHALL NOT act on it: it records the policy and
answers questions about it.

A rotation SHALL carry the interval to the version it creates.

The interval SHALL be distinct from expiry, which deletes.

#### Scenario: The policy survives the rotation that honours it

- **WHEN** a secret declaring a rotation interval is rotated
- **THEN** the new version carries the same interval

#### Scenario: Nothing happens on its own

- **WHEN** a secret's rotation interval passes
- **THEN** the secret is unchanged and still readable, and no job is created

### Requirement: Secrets past their rotation interval can be listed

The system SHALL answer which secrets have not been rotated within their declared interval,
computed from when each last changed.

Secrets declaring no interval SHALL NOT be reported.

#### Scenario: What is due can be asked for

- **WHEN** overdue secrets are listed
- **THEN** the result holds exactly those whose last change is further back than their interval

#### Scenario: Rotating one settles it

- **WHEN** an overdue secret is rotated
- **THEN** it is no longer reported as overdue

## MODIFIED Requirements

### Requirement: A value is replaced only by a successful rotation

Replacing a secret's value SHALL require a grant, and the new value SHALL become current only if
that grant succeeds.

While a rotation is in progress the new value SHALL be stored but SHALL NOT be readable, listed,
or provided to any grant.

If the grant fails, the system SHALL discard the new value and leave the previous version current
and unchanged.

Any identity permitted to invoke a grant SHALL be permitted to rotate through one. Rotation widens
no authority: the grant was approved by a human, the value is generated by the system and returned
to nobody, and every attempt is audited.

#### Scenario: A successful rotation

- **WHEN** a rotation's grant exits successfully
- **THEN** the new value becomes the secret's current version

#### Scenario: A failed rotation changes nothing

- **WHEN** a rotation's grant fails
- **THEN** the secret's current value is the one it had before, unchanged
- **AND** the new value is not retained

#### Scenario: A pending value is invisible

- **WHEN** a rotation is in progress and the secret is read or listed
- **THEN** the previous value is what is returned, and the pending one is not mentioned

#### Scenario: An agent rotates through an approved grant

- **WHEN** an identity with the agent role rotates a secret through a grant that declares it
- **THEN** the system performs it, as it would for any identity that may invoke that grant

#### Scenario: A grant that does not declare the secret cannot rotate it

- **WHEN** a rotation names a grant that does not declare the secret being rotated
- **THEN** the system refuses it
